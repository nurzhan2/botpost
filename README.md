# Бот-дайджест «Семейный вестник» (aiogram)

Обычный Telegram-бот. Ловит новые посты канала-источника, отсеивает спам,
особые новости публикует отдельными постами, остальное — дайджестом по 10 новостей
раз в день в канал-получатель. Старые новости заливаются отдельным скриптом.

## Как это работает
- **Источник:** `@semyadruj` — бот должен быть там **админом** (иначе не видит посты).
- **Получатель:** `@Friendl_family23` — бот **админ** с правом публикации.
- **Спам-фильтр:** вакансии / «зарплата от…» / «пиши в лс» выкидываются
  (`config.py → SPAM_PATTERNS`, регулярки с границами слов). Настоящей новостью
  считается пост с маркером-кружком (`⏺` `🔴` `⚪` `🔵`) или хэштегом
  `#…Епархия` / `#…Благочиние`.
  Маркер распознаётся в обоих написаниях — с вариационным селектором U+FE0F и без
  него; сравнение идёт после `filters.strip_vs()`.
- **Альбомы:** несколько фото с одной подписью собираются в одну новость
  по `media_group_id`; подпись берётся из того кадра, где она есть.
- **Отдельные посты:** тема «Твоя жизнь до рождения» и фамилии председателей
  (`config.py → CHAIRMEN_SURNAMES`). Для новых постов копируются вместе с фото.
- **Дайджест:** копится до 10 новостей, раз в день. Если меньше, но висит дольше
  `FLUSH_AFTER_DAYS` — публикуется всё равно. Длинный дайджест бьётся на несколько
  сообщений (лимит Telegram 4096 символов).

## Важное ограничение Bot API
Бот видит только **новые** посты — те, что появились после добавления его в админы.
Старую историю (с апреля/мая) заливаем отдельно, см. «Бэклог».

## Установка и запуск
```bash
pip install -r requirements.txt
cp .env.example .env          # вписать BOT_TOKEN от @BotFather
python main.py
```
1. `@BotFather` → создать бота → `BOT_TOKEN`.
2. Добавить бота **админом** в `@semyadruj` и в `@Friendl_family23`.
3. Запустить. Новые новости пойдут в очередь и опубликуются в `POST_TIME`.

## Бэклог (старые новости)
1. Telegram Desktop → канал-источник → ⋮ → Export chat history → формат **JSON**.
2. Сначала посмотреть, что попадёт в очередь, ничего не записывая:
   ```bash
   python import_history.py result.json --since 2026-04-15 --dry-run
   ```
3. Убедились — залить:
   ```bash
   python import_history.py result.json --since 2026-04-15
   ```
   Импортированные постятся текстом, без фото — живых оригиналов у бота нет.
   Тексты проходят те же фильтры, что и живая лента. Повторный прогон того же
   файла ничего не задваивает (идемпотентность по хешу текста), так что скрипт
   безопасно запускать несколько раз.

## Деплой на Railway
Бот — фоновый процесс (worker), без веб-порта. Файлы `Procfile` и `railway.json`
уже настроены (`python main.py`, автоперезапуск при сбое).

1. Залить проект в приватный репозиторий на GitHub (`.gitignore` уже прячет `.env` и `bot.db`).
2. Railway → New Project → Deploy from GitHub repo → выбрать репозиторий.
3. **Variables** (Settings проекта):
   - `BOT_TOKEN` = токен от @BotFather
   - `DB_PATH` = `/data/bot.db`
   - `ADMIN_IDS` = ваш telegram id (узнать у @userinfobot) — для `/status` и `/testpost`
   - `SOURCE_TG_CHAT_ID` = числовой id канала-источника (надёжнее username;
     если не задан, матч идёт по `SOURCE_TG_USERNAME`)
   - `TARGET_TG_CHANNEL` = канал-получатель (можно переопределить, не трогая код)
   - `VK_GROUP_TOKEN` и `VK_CHAT_ID` = токен сообщества и id беседы (когда будет).
     Пока `VK_CHAT_ID` не задан или `<=1`, VK-поток не запускается вовсе.
4. **Volume** (обязательно): добавить том и примонтировать в `/data`. Без тома при
   каждом передеплое база стирается и старые новости публикуются повторно.
5. Deploy. Логи — во вкладке Deployments.

Всегда-онлайн-процесс тарифицируется (~5$/мес после триала) — заранее решить, кто платит.

Первый прогон удобно делать на **тестовом** канале-получателе: выставить
переменную `TARGET_TG_CHANNEL` на свой тестовый канал, убедиться, что дайджест и
отдельные посты выходят как надо, потом вернуть боевой.

## Что осталось настроить
1. `CHAIRMEN_SURNAMES` — 5 фамилий председателей.
2. Фото в дайджесте: сейчас дайджест текстовый (как в примере). Отдельные посты для
   новых новостей идут с фото. Если нужно иначе — правится в `bot.py`.

## VK (ВКонтакте)
Официальный путь — сообщество-бот в беседе (без user-токена, без серых схем).

Настройка сообщества (один раз):
1. Создать сообщество VK (или взять существующее прихода).
2. Управление → Работа с API → **Long Poll API**: включить, версия 5.199;
   типы событий → «Входящее сообщение» — вкл.
3. Управление → **Сообщения** → включить сообщения сообщества.
4. Управление → Настройки → Возможности ботов → «Добавление в беседы» — разрешить.
5. Работа с API → **Ключ доступа** → создать → в `.env` как `VK_GROUP_TOKEN`.

Дальше:
- Админ беседы **добавляет сообщество в беседу** (как в телеге «добавьте бота»).
- В `config.py`: `VK_GROUP_ID` = id сообщества, `VK_CHAT_ID` = id беседы
  (открыть беседу на vk.com/im → в адресе `sel=cN`, N — это chat_id).

Одним токеном сообщества работает и живой приём (Long Poll), и заливка старого:
```bash
python import_vk.py        # старьё из беседы с VK_START_DATE
```
VK-новости публикуются текстом (перенос фото из VK в Telegram — отдельная доработка).

## Диагностика

На старте бот сам проверяет доступ к обоим каналам и свои права там
(`preflight`). Если он не админ в источнике — в логах будет WARNING, и это
означает, что посты оттуда не придут в принципе.

Каждый пост логируется с явной причиной исхода:
`queued: digest|special` либо `skip: not_source | seen | spam(шаблон) |
no_marker | empty_text`. Если за `FLUSH_AFTER_DAYS` дней в очередь не попало
ничего, а посты приходили — в лог падает WARNING «фильтр отсёк 100% постов».

Команды в личке боту (только для `ADMIN_IDS`):
- `/status` — размеры очередей, возраст старейшей записи, путь и размер файла БД,
  время следующего запуска джобы и её таймзона, счётчики с момента старта.
- `/testpost` — принудительно выполнить публикацию прямо сейчас.

Проверить фильтры на наборе образцов, не запуская бота:
```bash
python scripts/diag_filters.py
```
